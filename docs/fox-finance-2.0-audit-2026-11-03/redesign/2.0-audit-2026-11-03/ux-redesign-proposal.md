# Fox Finance 2.0 UX 重设计方案

2026-11-03，提案，等待批准。关联：[现状审计](ux-audit.md)、[信息架构](information-architecture.md)、[交互流程](interaction-flows.md)、[设计系统](design-system.md)。

## 产品方向

保留“我的钱是否帮助我成为更好的自己”的核心，重新组织为“随手记、看得准、能复盘”。财富森林承载氛围和总体判断；交易工作页承载处理效率；年轮承载回顾、个人文字与长期关系。无需复制通用 SaaS 仪表盘或为新版本替换框架。

本次已有真实实现值得保留：本地品牌图片、交易类型基础、日期分组与标签、Obsidian命令和事件、Canvas图表和生成笔记能力。应调整职责及数据来源，避免全部推倒。现有规则月度点评先成为“可解释观察”，不能升级命名为AI分析。

## 四个核心画面

### 财富总览

顶部森林品牌与当前时间范围、来源状态，右侧持续可见“记一笔”。主体左侧以净资产和本月净收支建立层级，右侧轻量树木/年轮线条表现长期轨迹。下方为现金账户余额、投资估值与预算剩余，点击进入有价值的明细；近期交易与异常待办放同一阅读路径。只提供一个主趋势，能下钻到支持该结论的交易。资产卡完整汇总，不用前三账户当总额。

### 快速记账

金额是视觉和键盘起点。支出/收入/转账主切换，今天、最近账户、近期分类是可更改的默认芯片；备注与标签展开后再填写。保存/再记一笔让连续记账留在同一任务。首次无数据不猜账户；显示待分类比提交错误分类更诚实。自然语言是另一个输入入口，与表单共享同一预览草稿，先规则、后可选Ollama，保持无AI可用。

### 交易管理

持久页面取代多层大弹窗。日期范围可直达月份/年度，搜索与过滤组合；选择行后详情/编辑在侧边展开。批量分类、标签、导入审核先做；批量删除后置并有影响确认。保存后筛选、滚动、选择保留。新旧数据冲突、疑似重复、导入格式错误各有明确文案和恢复动作。

### 预算与分析

预算是资源分配，采用余额式描述“还可用/已超出”；月度和年度明确拆分，分类范围与退款口径可查看。年轮分析先回答净资产怎么变、钱花在哪里、哪些变化值得复盘；不用堆无基期饼图。月度复盘把事实、自动观察、用户感受、下月行动放在连续任务中，保留原有笔记和手写内容。

## 优先级与依赖

| 批次 | 范围 | 前置与退出标准 |
|---|---|---|
| A：数据可信 | 完整资产汇总、历史期末、退款/转账口径、编辑保真、防重提交、删除恢复策略 | 权威数据契约与模拟账本真值测试；不是仅改文案 |
| B：高频任务 | 快记与交易工作页、账户/预算入口、连接与差异状态 | 交易CRUD及版本冲突可用；无服务可保留草稿 |
| C：视觉一致 | token、层级、容器适配、图标与可访问性 | 结构确定后组件复用；键盘/缩放/主题验证 |
| D：长期价值 | 月度复盘、历史趋势、可选自然语言与Ollama | 历史数据对账与镜像保留人工内容通过 |

视觉设计和模拟交互可与桥接设计并行；生产写路径和迁移必须先通过数据安全门槛。绝不为了先展示新版界面继续向旧Markdown和新数据库双写。

## 原型范围与评审方法

独立原型应只使用内存中的合成示例，放置隔离 prototype 目录；不可连接 Obsidian API、真实数据库或真实财务路径，不加载外部资源。至少可切换财富总览、交易管理、预算与分析，打开快记、增加/编辑/删除模拟交易，刷新页面恢复模拟初始值。页头必须写“设计原型·示例数据”，不能让操作看起来已同步真实账本。

本子任务没有操作浏览器/生产插件，不将静态源码阅读视为视觉验收。原型的实际交付与检查情况由项目总入口记录；若由其他子任务制作，链接该产物而非再建第二份。这里定义评审任务：

1. 仅输入金额保存常用支出，确认默认账户/分类是否可理解。
2. 修改转账去向并返回筛选列表，确认未改字段保持原值。
3. 找到本月剩余预算并下钻该分类交易。
4. 查看历史月份期末资产和复盘，不与当前余额混淆。
5. 模拟离线保存/镜像失败/手改差异，能说清哪一步成功、下一步怎么办。

## 建议确认的决定

- 同意五主入口“财富森林/交易/账户/预算/年轮”，分类作为账户下二级管理。
- 同意以金额优先、最近有效账户默认、可见待分类减少输入；首次使用仍需明确选择账户。
- 同意数据区实色、森林装饰保留、星空主题可选；不强制沿用当前紫色玻璃作为所有组件样式。
- 同意Android首版用ZCashflow，Fox先保证桌面窄分栏可用；手机Obsidian全功能后置。
- 同意自然语言先本地规则预览，Ollama可选后置，不自动写账。
- 同意年轮将生成区域与手写复盘分离；历史笔记保留，冲突先展示不覆盖。

这些是建议，不能以本文件替代批准。当前阶段只完成审计与设计规划，下一阶段的生产代码改造、数据库/API实现、迁移与发布均未启动。
