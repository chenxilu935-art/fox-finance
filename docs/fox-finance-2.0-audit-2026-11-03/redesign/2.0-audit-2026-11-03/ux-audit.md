# Fox Finance 2.0 UX/UI 审计

审计日期：2026-11-03。范围：本地已安装插件源码，非 README 推断；没有操作真实账本或运行会写数据的 UI。本报告为代码与交互结构审计，未宣称完成真实窗口截图、对比度实测、屏幕阅读器或用户可用性测试。生产视觉需要下一阶段在模拟数据环境验证。

## 总体结论

产品已有可辨识的森林/星空资产、交易 CRUD、月度年轮和预算追踪，是可用的个人插件基础；不是完整的成熟财富管理工作台。最先改的是指标可信度、记账默认值与连续操作、管理入口和错误状态。保留品牌资产，重排任务与阅读层级；不需要先迁移框架或接入图表库。

文档基线存在时效差：`docs/product-requirements.md` 标注 0.6.1、2026-08-04，而 `docs/execution-plan.md` 头部仍为 0.5.0、2026-07-27，正文又包含 0.6.1。功能判定以代码为准，不将历史勾选视为验收证据。

## 长期使用与跨窗口

源码 styles.css 未找到 `@media`；首页固定六列、流水固定多列、复盘双列（`:198/:385/:920/:1207`），应视为窄分栏风险，不宣称已复现溢出。响应规则按视图容器宽度而非显示器宽度：宽屏双区、普通分栏单区、紧凑交易行。320、480、768、1280 CSS px，125%/200% 缩放、键盘全流程需后续验证。

Canvas 已考虑 devicePixelRatio（`finance-review-view.ts:277`），也有鼠标 tooltip；未见相等的键盘/文本访问和容器变化自动重绘。保留 Canvas 可行，补同口径数据表和 resize 即可，不必先换库。

当前数据加载在 refresh 中 await 完成后重绘；缺统一加载/过期/重试状态，异步失败可能留下空白或旧值。未来桥接离线时必须标“桌面数据截至…”，草稿保存与权威保存成功区分；不能把手机尚未同步的新账误称已更新。

## 建议排序与衡量

1. P0：汇总、编辑状态、历史余额、删除和重复提交，先用模拟数据做真值验证。
2. P1：统一交易页+快捷记账、独立账户/预算、连接与差异待办、可恢复反馈。
3. P2：设计 token、图表可访问性、容器适配、轻量动效与主题。

无需重做：已有本地图片品牌、日期分组、标签芯片、基础 Canvas、Obsidian 命令和事件。自然语言输入先做确定规则预览，Ollama 延后。

衡量提案（非已测结果）：常用支出在预设有效时仅输入金额即可保存；金额焦点到保存全键盘完成；保存后保留筛选；任何连接失败不显示“已保存”；转账不增加总收入支出；屏幕隐藏模式不在 tooltip 继续泄露。真实任务时间需先建立 0.6.1 基线。

补充代码核对：`finance-review-view.ts:66` 年度流水缓存仅在年份变化时重读；同年新增/编辑交易触发 refresh 后，年度预算可能仍用旧缓存。应由权威变更版本驱动失效，而不是为此增加复杂缓存框架。`fox-dashboard/view.ts:1246` 已调用 Fox Finance dataLayer 取数据，未来重点替换其摘要计算/展示口径并保证同源，不应误写为工作台当前完全自行读取 Markdown。
